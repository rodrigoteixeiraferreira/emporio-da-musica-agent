## 2. Standing rules (not negotiable)

1. **Python** is the main language (the statement's only technical constraint).
2. **Model: Gemini API, free tier**, through the official `google-genai` SDK. No paid API.
   - The model is configurable via `GEMINI_MODEL`. Before fixing the default, check the official documentation (ai.google.dev) for which Flash model is on the free tier **today** and whether it supports function calling. Record in the README the model and the date it was checked.
   - The key lives in `.env` (`GEMINI_API_KEY`) and **never** goes into the repository. Version a `.env.example` and make sure `.gitignore` covers `.env` before the first commit.
   - The free tier has request limits: handle error 429 with retries and increasing waits.
3. **The AI interprets and orchestrates; code calculates.** Price, discount, installment, shipping, stock, order status and exchange deadlines always come from a tool (SQL/Python), never from the model. The store manual demands the same (section 7.1: "never give information about prices, stock or deadlines without checking the system").
4. **No LangChain, LangGraph or vector database.** The SDK's native function calling, in an explicit, readable loop. Justify it in the README.
5. **Policies in the prompt, no RAG.** The manual has 8 pages. Extract the PDF text once into `data/processed/policies.md` (the extraction script is versioned) and put the whole manual in the system prompt. RAG goes into the README as a next step, for when the manual grows.
6. **Customer data.** Order status only with the order number **and** the e-mail or phone of that order's customer. Never show another customer's data. The manual does not define this check; it is an assumption backed by section 9 (LGPD). Document it.
7. **Text similarity never confirms a product.** If the requested name is ambiguous or approximate, the tool returns candidates and the agent asks which one it is.
8. **Example conversations are real outputs of the code.** They are generated by a script, with model, reference date, generation date and commit hash in the header. Never written or edited by hand (not even by you). If an output is bad, fix the code or the prompt and generate it again.
9. **Git:** small, real commits, messages in English (conventional commits), push at the end of each stage. No force-push, rebase or squash of the history.
10. **Test before closing a stage.** Tool tests do not depend on the model API.
11. **Do not invent store data.** If the manual and the tables do not answer, the agent says it does not know and forwards to human service, with the contact from the manual.

## 3. The material and what is already mapped

**Tables** (`data/*.csv`, UTF-8; file names contain spaces):
- 64 products: 62 `active`, 2 `discontinued`, 1 `coming_soon`; 2 out of stock.
- 49 customers.
- 20 orders: delivered 7, confirmed 4, pending 4, cancelled 4, shipped 1. Only shipped and delivered ones have tracking and estimated delivery. Cancelled ones carry the reason in `notes`.
- 21 order items. The item does not carry the price at the time; the order value is in `orders.total_brl`.
- 24 promotions, only 4 active (`is_active = 1`).
- 9 categories.
- The products' `specs` is JSON (top, strings, pickup, etc.), useful for searches like "violão com captação".

*(Note added during the session: the real counts are 65 products, 50 customers, 22 order items and 25 promotions; the statuses and the 4 active promotions match. Tests use the real counts.)*

**Manual** (`data/políticas_da_loja.pdf`, 8 pages): opening hours; payment and installments; exchanges and returns; shipping; promotions; WhatsApp service (tone, flow, special situations); warranty; LGPD.

**Inconsistencies in the manual.** Resolve each one, document it under *Assumptions* and make the agent follow the choice:
- **WhatsApp:** the cover and the data table give (67) 3341-4444 as "Phone / WhatsApp"; section 7 says the WhatsApp is (67) 3321-4500.
- **E-mail:** appears with and without an accent (`contato@emporiodamusica.com.br` × `contato@empóriodamusica.com.br`). Use the version without the accent.
- **Installments:** the table in section 3 says "up to 12x, minimum installment R$ 100". Section 3.1 says: up to 3x with no minimum (except below R$ 50); 4x to 6x, minimum R$ 80; 7x to 12x, minimum R$ 100. Use 3.1, the more specific one.
- **Catalog:** the manual mentions "more than 300 instruments", but the table has 64. The table wins.

**Dates:** orders go from October/2025 to March/2026.
- The agent's reference date is configurable (`STORE_TODAY`; default = today).
- Use the `America/Campo_Grande` time zone (UTC-4) to tell whether the store is open.
- Generate the examples with a reference date right after the last order (22/03/2026), for example 25/03/2026, and state that date in each example's header.
- Assumption to document: a delivered order was received on its `estimated_delivery`.

**Rules that become code, not prompt:**
- **Final price:** with an active promotion, the list price with the discount, always shown with the original price and the percentage (section 6.2).
- **PIX:** 5% discount **only** without a promotion, because promotions do not stack (6.2).
- **Installments:** maximum number of installments by the 3.1 bands. Combining payment methods only above R$ 2,000.
- **Shipping in the metropolitan region:** free above R$ 500; below, R$ 35. Other cities depend on a quote by CEP (postcode): do not calculate, explain and forward.
- **Exchange and warranty deadlines:** regret, 7 days from receipt; defect, 30 days from purchase; preference, 7 days; legal warranty, 90 days from receipt.
- **Opening hours:** Monday to Friday, 9:00 to 18:00; Saturday, 9:00 to 13:00; Sunday and holidays, closed.

## 4. Target architecture

```text
emporio-da-musica-agent/
  data/
    raw/                 # the CSVs and the PDF as received
    processed/           # policies.md (generated and versioned)
  src/emporio_agent/
    db.py                # loads the CSVs into an in-memory SQLite, with types and normalization
    policies.py          # extracts the PDF to policies.md
    pricing.py           # final price, PIX, installments, shipping — pure, tested functions
    tools.py             # the tools exposed to the model
    prompts.py           # system prompt: persona + rules + manual + reference date
    agent.py             # function-calling loop with Gemini, history, retry on 429
    cli.py               # command-line interface
  scripts/
    extract_policies.py
    run_examples.py      # runs the scenarios on the real agent and writes examples/*.md
  examples/              # 3 to 5 real conversations
  tests/
  README.md
  .env.example
  requirements.txt
```

**Tools.** Names are suggestions; the behaviour is mandatory:
- **`search_products`** (text, category, min/max price, include unavailable = no): returns products with final price, discount and stock. By default excludes discontinued, "coming soon" and out-of-stock items, but says if there are any.
- **`get_product`** (name or id): finds the exact product, or returns candidates. Brings:
  - the price breakdown (list, active promotion, PIX, maximum interest-free installments and installment value);
  - stock, status and specs;
  - alternatives from the same category when the product is out of stock or discontinued (section 7.3).
- **`get_order_status`** (order number, e-mail or phone): status, dates, tracking and cancellation reason. Refuses if verification does not match.
- **`check_return_eligibility`** (order, verification, reason: regret | defect | preference): counts the days against the manual's deadlines and returns eligible or not, with why, plus the alternatives (legal or manufacturer's warranty).
- **`list_active_promotions`** (optional category).
- **`get_store_status`**: open or closed now, from the reference date and the time zone.
- **`escalate_to_human`** (summary, contact): writes to `data/runtime/handoffs.jsonl` (outside git) and returns a protocol with a 24-business-hour return time (complaint, section 7.3).

**The agent:**
- The system prompt follows the tone of section 7.1 ("informal but professional", "a friend who knows music"), the flow of 7.2 and the special situations of 7.3.
- Scope: the store sells **only instruments**. Accessories are politely redirected; topics outside the store get a short answer and go back to service.
- Loop: model → tool calls → results → model, with an iteration limit per message.

**Interface and history:**
- CLI: `python -m emporio_agent`, with `--show-tools` (shows the tools called) and `/reset`.
- In-memory history during the session. Persisting across sessions goes into the README as a next step.
- On Windows, force UTF-8 console output for accents.
